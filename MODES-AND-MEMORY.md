# Elias EIE — Modes, Memory and Human Context

## Standard

The baseline interaction mode for ordinary conversation and provider response handling. A useful baseline for comparing the app's specialized modes, not an independent security or truth guarantee.

## High Precision Mode (HPM)

An interaction pathway designed to encourage careful claim handling, explicit uncertainty, separation of evidence and inference, and refusal to turn missing evidence into unsupported certainty. Existing public HPM repositories and local standalone evaluations have their own evidence boundaries; they are not automatically EIE end-to-end assurance.

## Emotional Programming Layer (EPL)

EPL is an AI-output and interaction governance contract informed by user-defined qualities, principles and constraints grounded in the LOVE Formula. It guides how AI interprets input and produces responses, including care, boundaries, uncertainty and non-diagnostic communication. It does not imply human emotional experience, diagnosis, treatment or clinical competence. Model-level guidance must be distinguished from controls independently enforced and tested in Python. Pilot feedback does not establish clinical effectiveness.

## Memory governance

EIE distinguishes contextual information, user-suggested memories, saved/approved memories and governing application authority. Memory may affect context but does not on that basis gain instructions, credentials, privileged access or execution permission. The precise behavior of memory approval, export and erasure must be verified against deployed operations and privacy requirements before contractual promises are made.

## Knowledge library — not currently a released EIE feature

A curated offline knowledge store has been proposed as separate from the language model and conversational memory. It would require validation, approval, provenance, versioning, integrity, permissions and freshness boundaries. It is **planned**, not present-tense pilot functionality.
